## 当前测试模式：后台免密码（2026-11-18）

**当前已部署** `MSWQ_TEST_OPEN_ADMIN = true`。直接访问 `/admin` 可以编辑、保存、上传和发布，不需要设置 `ADMIN_PASSWORD` 或登录。原版话术编辑器 `/admin/legacy-editor` 同样免登录。**任何知道后台 URL 的访问者都可修改内容，仅适用于测试环境**。

想恢复 MSWQ 的登录限制，可把 `src/worker.js` 顶部常量改回 `false`、配置 Cloudflare Secret `ADMIN_PASSWORD`，然后重新部署。**原来的 `ms-khmb` Worker 代码和登录机制没有被修改**；在 MSWQ 测试后台进入「DOCX 模板后台」时，默认以管理员模式工作，不再显示登录、改密码或退出管理员按钮。MSWQ 直接操作旧工具共用的 DOCX D1/KV 数据，所以在 MSWQ 中修改/删除模板也会影响旧工具可见的模板。

MSWQ 使用 **Cloudflare Workers + 独立 D1 + 独立 R2**。后台编辑流程和文档，前台仅显示已发布内容。项目源代码在 \`main\` 分支。

## 已修复：新内容类型发布失败（D1 约束升级）

旧 MSWQ D1 的 `items.kind` 仍有只允许 `personal/group/document/page/link` 的 CHECK 约束，导致上线个人名片、网址收藏及自定义分类后，点「保存并发布」返回 HTTP 500。已在独立的 `mswq_db` 中备份原有条目、复制校验、重建 `items` 表并重建 `idx_items_public` 索引；改由 Worker 的 `normalizeItem` 及 `validateSpecialContent` 验证合法内容类型。现有已发布页面、内容 ID、路径和版本保留。生产库已完成升级，不要重复执行迁移。

`schema.sql` 已同步适配新数据库；`migrations/002-expand-item-kinds.sql` 说明已有旧库如何备份、创建新表，并在验证后手工完成替换。数据库验证包括模拟 `profile`、`bookmarks` 和 `custom_<id>` 三种已发布内容的写入/读取/删除，所有临时数据均已清理。

## 个人名片视频、媒体放大、链接复制与分类管理（v1.3.0）

- **个人名片**：字段类型可自由选择文字、链接、图片或视频；视频支持 MP4、WebM，上传至 MSWQ 独立 R2。单段视频最多 50 MB，图片等原有素材仍限制 12 MB；图片与视频均支持从素材库中选择，编辑上传或替换不改变已发布页面的公开路径。
- **前台媒体预览**：点击图片/视频进入全屏浮层（视频使用浏览器原生播放控制），提供「保存 / 下载」按钮。资源接口支持 `?download=1` 的附件下载响应和视频按字节 Range 读取（206 部分内容），方便播放和拖动进度条。
- **前台复制链接**：个人名片里的网址项目以及网址收藏夹的每条地址新增「复制链接」按钮；外部工具类型的公开页面也可以复制目标链接。
- **前台分类管理**：后台左侧新增「分类管理」，支持 `/admin?tab=categories` 直接进入。管理员可以隐藏/恢复任意内置或自定义类型在公开首页的**分类筛选按钮**。内置类型不能永久删除，以防原有业务类型损坏；没有关联内容的自定义分类可直接删除。有内容的自定义类型若不希望展示，使用“隐藏前台”，或者先更改这些内容类型再删除。删除分类不会删除内容，`全部内容` 始终保留。
- 分类数据通过原有独立 D1 `settings.custom_types` 和新增 `settings.hidden_types` 持久化，独立于原 MS_KHMB 模板库。**不需要数据库迁移**。

## 网址收藏和个人名片模块（v1.2.0）

后台直接入口：
- `/admin?tab=bookmarks`：**网址收藏**。可以创建多个收藏夹，在每个收藏夹中逐条添加网址名称、完整 HTTP(S) 链接、说明，以及直接上传或从素材库选择封面图片。支持编辑、删除、上下排序、保存草稿、发布和下架。发布后首页出现“网址收藏”内容卡片，点击进入本收藏夹网页卡片列表，每个网址在新标签页打开。
- `/admin?tab=profile`：**个人名片**。新建后**没有预置姓名、电话、邮箱等字段**。通过“＋ 文字标签 / ＋ 网址标签 / ＋ 图片标签”自由新增、命名、编辑、删除和排序字段。可直接上传 JPG/PNG/WEBP/GIF，或从现有素材库选择图片。名片主页标题/路径仅在可折叠“页面发布设置”中管理，不会自动生成个人信息字段。前台逐项显示标签与内容，并提供文字复制、网址打开和图片展示。
- 两者都沿用 D1 `items` 的 `kind` 与 `content`，类型分别是 `bookmarks`、`profile`；复用原有草稿 / 发布 / 公开路径 / 版本历史 / JSON 备份。两者都可创建多份，每份拥有独立 `/view/<slug>` 链接，不需要改动数据库结构。
- **仅点击“保存并发布”或“发布”后，内容才会出现在公开前台**；草稿不对外显示。测试环境 MSWQ 后台仍免密码，所以创建真实名片时不要在发布之前填入不打算公开的个人资料。

## DOCX 模板专属分享链接（2026-11-18 更新）

在 MSWQ 的「DOCX 模板后台」点击某个模板的「复制专属链接」，现在生成 `https://mswq.mosen6266-ms007.workers.dev/view/docx-workspace?template=<模板ID>`。复制出的直达链接保留 MSWQ 前台导航和左上「← 返回」按钮，并以对应的 `template` 参数在右侧全屏 DOCX 工作区中选择正确模板，不再指向裸 `/docx?template=...` 页面。过去生成的 `/?template=<模板ID>` 与 `/docx?template=<模板ID>` 链接也兼容前台框架；独立内嵌工作台使用 `/docx?template=<模板ID>&embed=1` 防止循环嵌套。普通 `/docx` 入口及原 MS_KHMB 服务仍不变。

## 前台 DOCX 页面（当前上线）

前台内容卡片「制作文件」在**当前标签页**打开 `/view/docx-workspace`；网页顶部保留与首页一致的 MSWQ 导航栏，并在左上角显示「← 返回」。顶部导航栏下方由 DOCX 填写工作台占满剩余整个浏览器视口；不会再用受限的普通内容详情页，也不会新建标签页或跳转到 `/docx`。通过 `/docx?template=<ID>` 生成的各模板专属分享链接依然可单独打开纯 DOCX 工作台，公开访客仍不可修改模板。后台 `/admin` 左侧的 DOCX 管理入口不受影响。

## 后台直接内嵌工具（当前上线）

MSWQ 后台 `/admin` 左侧菜单点击「原版流程编辑器」或「DOCX 模板后台」后，右侧整片工作区直接加载工具界面（完整视口高度、无外围标题栏及二次打开按钮），不再跳转或新建标签页。对应的独立路径 `/admin/legacy-editor`、`/admin/docx-editor` 仍保留作为同源内嵌页面。Worker 仅给这两个管理页面设置 `frame-ancestors 'self'`，其他来源无法嵌入。MSWQ 中的 DOCX 模板后台采用测试模式自动管理员权限，并复用原模板 D1/KV；原 `ms-khmb` Worker 自身独立登录规则不变。

## 自定义内容分类（当前上线）

在后台「内容管理」→「内容编辑」的**内容类型**下拉菜单底部，选择「＋ 新增分类…」，输入 1–30 字名称并保存。新分类会创建为持久的 `custom_<id>` 类型，自动成为当前内容的选定类型，并在后续编辑的下拉菜单、公开内容卡片与前台筛选项中显示；原来的个人流程、群剧本、DOCX 文档、自定义页面、外部工具类型保持不变。分类数据保存在 MSWQ D1 `settings.custom_types` 中，名称不能重复，最多支持 100 个新增分类。新类别的内容使用普通可编辑步骤，不改变 DOCX 等既有类型专属功能。当前仅支持新增；重命名、删除尚未开放。

- 修复旧版内嵌脚本插入错误：现在只在 HTML 最后真正的 `</body>` 前添加 `public/legacy-bridge.js`，不会再误插到导出查看版的模板字符串里，避免 `personalOfflineReaderMarkup is not defined`。
- 个人流程离线 HTML 查看版包含独立的渲染函数，即使群剧本工具脚本未就绪也能生成导出文件。
- 编辑器右下角和个人流程操作区均有「保存 / 发布到前端」。可以保存草稿、正式发布、更新以前发布的同一套流程，成功后返回 `/view/<slug>` 链接。发布时尽力同步附件，未能同步的附件会逐一提示。
- 「合并导出个人流程查看版」窗口现在有「☁ 发布所选到前端」，**每套选中的流程独立发布一条内容**（不是把所有流程合并成单个前端页面），逐套显示发布结果与链接。原「导出所选流程」继续生成离线合并 HTML，两项操作彼此独立。
- 编辑器本地数据使用当前 MSWQ 站点的浏览器存储，与原先 `file://` 编辑器并不自动共享；历史文件需先导入备份。正式发布的云端内容使用 MSWQ D1；页面发布状态不是浏览器本地状态。

### 原版话术流程编辑器
- 上传的完整 \`话术剧本流程编辑器(6).html\` 已保存在 \`legacy/flow-editor.html\`。
- 在受保护的 \`/admin/legacy-editor\` 内使用。右下角 **“发布到 MSWQ”** 按钮可把个人流程和群剧本直接保存到云端草稿或发布为分享链接。
- 同一份本地流程重复发布会更新已有内容，而不是自动重复创建。
- 原版编辑器仍使用浏览器本地存储：**从原电脑的 \`file://\` 版本首次转移旧数据，先在原页面“导出编辑备份 JSON”，在 MSWQ 的“导入与备份”导入**。不同网页域名不会自动共享 localStorage/IndexedDB。
- 个人流程/群剧本的公开查看页使用 MSWQ 只读呈现。少数原版的导航/关键词/样式细节及部分附件可能需要检查迁移效果；并不保证原界面的像素级复制。
- 编辑器点击“发布到 MSWQ”会尽力同步本地附件；超过文件限制、旧浏览器无法访问的附件需要手动在素材库补充。

### DOCX 模板工作台
- 从原生产 \`ms-khmb\` 的 HTML 获取并保留文档模板编辑能力，不修改原有 Worker/KV/D1。
- **公开 \`/docx\` 页面**使用文档查看和填写引擎，隐藏旧管理员登录/上传/删除控件；MSWQ 的代理只允许 GET 模板列表、指定模板版本和 DOCX 下载，服务端拒绝公开写入。
- **MSWQ 内嵌 \`/admin/docx-editor\`** 进入时默认管理员模式，无密码输入、登录按钮。其专属读写接口复用原 DOCX 业务处理逻辑和旧服务 D1/KV 存储（新增绑定 `DOCX_DB`、`DOCX_KV`），支持原有上传、修改、删除、排序和 Word 模板版本保护。原 `ms-khmb` 的代码和独立登录规则不变，**但两者使用同一份模板数据**。
- DOCX 模板文件和原版元数据仍存储在老 \`MS_KHMB\`，由 Cloudflare Service Binding 连接。MSWQ 不复制或覆盖模板数据。
- 公开 `/docx` 仍只能读取/填写/导出，不能修改模板。**测试阶段 MSWQ 后台无访问密码，知道 MSWQ 后台链接的人可以修改共享的 DOCX 模板数据；正式上线前必须恢复管理鉴权**。

## 源代码

- \`src/worker.js\`：Cloudflare Worker 服务、权限、数据库、上传和只读 DOCX 接口，以及 MSWQ 测试管理 DOCX 路由。
- `src/docx-admin-backend.js`：来自原 MS_KHMB 的 DOCX 业务接口，仅在 MSWQ 后台复用，管理权限由 MSWQ 处理。
- \`public/index.html\`, \`public/app.js\`, \`public/app.css\`：公开网站、流程阅读器、管理员界面、样式。
- \`public/legacy-bridge.js\`：原编辑器到在线发布系统的同步桥接。
- \`legacy/flow-editor.html\`：完整原版流程编辑器（在服务器端要求管理员身份）。
- \`legacy/docx-public.html\`：文档访客版，隐藏管理员入口。
- \`legacy/docx-admin.html\`：独立保存的旧文档管理版源码参考。
- \`schema.sql\`：D1 schema 初始化。

部署器把 HTML、CSS 和 JS 编译为 \`src/worker.js\` 中的 \`__MSWQ_ASSETS__\` 常量，并把 `src/docx-admin-backend.js` 嵌入 `__MSWQ_DOCX_API__`；该 Worker 已通过 Cloudflare API 发布。仅更改 GitHub 代码不会自动部署到线上；需要重新打包和上传 Worker。后台的内容修改直接写 D1/R2，**不需 GitHub 发布**。

## 安全说明与后续扩展

- 不会修改或重启 Telegram、Signal、MS_KHMB、授权系统等其他 Worker/数据库。
